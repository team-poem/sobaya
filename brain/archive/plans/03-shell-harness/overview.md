# Shell harness migration

The user explicitly requested reverting the Python implementation choice to
shell while preserving the agreed architecture, then committing and pushing.
The previous architecture approval did not authorize silently introducing a
new implementation language. This migration uses Bash 3.2, jq, Git and standard
utilities; test fixtures exercise actual Go/Node/Vitest but harness orchestration,
installation and regression coordination must not invoke Python.

Scope: root harness only, independent app repositories preserved. Port worker
state schema and approval semantics, test/header protection, actual runner
execution evidence, shared hygiene, process cleanup, lock, commit recovery and
fresh independent review. Convert all regression scenarios, rather than removing
tests merely to remove Python files. Preserve version1 on-disk approval state.

## Completed validation

Converted all runtime, utility, hook and regression entry points to shell.
The old version1 approval schema remains readable, including fractional timestamps,
existing usage and accumulated calls. Removed all ten Python implementation and test files
introduced by the previous change and their generated bytecode caches.

Integrated aggregate validation passed: 38 contract cases (mapping all original
36 method behaviors), 27 runner cases (original25 plus two hidden-index attacks),
67 tool checks, and the separate next/probe/gate shell regressions. Actual Go,
Node and Vitest ran; fake workers and a forbidden-interpreter sentinel established
that the harness used no Python or live model API.

Independent review reproduced a false PASS using Git skip-worktree flags. Both
skip-worktree and assume-unchanged are now rejected before approval, after workers,
before commits and in the gate; regression proves HEAD and edits remain preserved.
The review found no further concrete critical/high issue in its bounded scope.
The port also corrected jq empty-match classification and fail-open process
inspection; syntax errors never authorize a worker, unknown process state blocks.

The user explicitly authorized committing and pushing this shell migration to the
existing Sobaya repository. Independent app repositories remain untouched.
