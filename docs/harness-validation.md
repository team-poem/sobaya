# 하네스 전환 및 검증 기록

2026-09-10. 공통 AGENTS.md·명시적 모델 정책·승인 기준·항목별 검증 구조는
유지하면서 하네스 구현과 테스트를 셸로 통일했습니다.

## 사용자 지적과 수정 범위

사용자가 승인한 것은 하네스 아키텍처였습니다. 이를 Python 구현 추가까지
승인한 것으로 해석한 것은 에이전트의 잘못이었습니다. 하네스는 Bash 3.2·jq·
Git·표준 Unix 도구를 사용합니다. 앱 자체의 Go·Node·Vitest 테스트 러너는 별도입니다.
다른 런타임 언어를 도입하려면 구현 전에 명시적으로 승인받아야 합니다.

승인된 명세·테스트와 모델 선택 규칙은 언어 변경을 이유로 완화하지 않습니다.
기존 Python 검사의 통과 기록은 이전 구현에 대한 결과이며 현재 셸 구현의
검증 결과로 재사용하지 않습니다. 과거 플랜은 역사 기록으로 보존합니다.

## 검증 경계

사람의 명세·테스트 검토 → 커밋된 기준 승인 → 테스트 하나 삽입 → 실패 근거
확인 → 구현 워커 → 보호 파일 검사·포맷·린트·전체 테스트 → 체크·커밋 → 최종
게이트 → 별도 맥락의 읽기 전용 리뷰 순서로 진행합니다. 이미 통과하는 항목은
그 사실을 기록하고 구현 호출을 생략합니다. Go 미정의 심볼의 build-red는
별도 승인 옵션을 쓸 때만 허용하며, 최종 성공은 실제 실행 결과로 판단합니다.

| 경계 | 회귀 검사 |
|---|---|
| 승인 | 명시적 승인 필요, 재실행 시 기준 유지, 변경 기준은 명시적 재승인 |
| 테스트 | 본문·헤더·픽스처 변조 거부, 주석·skip·이름만 있는 가짜 성공 거부 |
| 실제 실행 | Go JSON·Node TAP·로컬 Vitest JSON에서 실행과 성공 확인 |
| 작업 상태 | staged·untracked 변경 거부, 자동 stash/reset 없음, worktree와 작성자 잠금 |
| 재개 | 인계 근거 보존, 누적 호출 예산, 준비 실패·커밋 실패 복구 |
| 커밋 | 검증한 내용과 실제 tree·parent 비교, 미검증 결과 거부 |
| 취소 | 작업자 종료 전 잠금 해제 방지, 살아 있는 고아 작업자 거부 |
| 정리 검사 | Git 훅이 없어도 포맷·린트 실행, gofmt 목록 출력도 실패 처리 |
| 리뷰 | 새 맥락, 저장소·index 변경 거부, 확인한 HEAD에 연결 |
| 어댑터 | 가짜 Codex 실행 파일로 argv·스키마·역할·사용량 이벤트 확인 |
| 설치 | 기존 사용자 훅 보존, root/worktree 지원, 실제 Git 훅 경로 확인 |
| 구현 언어 | Python 인터프리터 호출과 저장소에 있는 Python 하네스 소스 거부 |

`tests/test-runner.sh`는 기존 런타임 검사 25개의 동작과 주요 단언을 유지하며,
`skip-worktree`·`assume-unchanged`로 미커밋 구현을 숨기는 워커를 차단하는
검사 2개를 추가했습니다. 커밋 전 거부, 기존 HEAD 유지, 미완료 상태와 진단,
조사할 수 있도록 플래그·작업 파일을 보존하는지 확인합니다.
잠금 검사는 내부 잠금 방식 대신 실제 동시 작업자 거부로 확인하며, 취소 검사는
백그라운드 Bash의 신호 상속을 고려해 SIGTERM으로 종료 코드 130과 늦은 쓰기
차단을 확인합니다. 가짜 워커도 셸이며 유료 모델 세션을 호출하지 않습니다.

## 재현

```sh
bash tests/run.sh
bash scripts/setup.sh . --check
bash scripts/brain-index.sh . --check
bash scripts/workspace-check.sh .
git diff --check
```

`tests/run.sh`가 계약·런타임·도구 검사와 셸 회귀 검사를 묶어 실행합니다.
일부 검사를 통과했다고 전체 통과로 보고하지 않습니다. 실제 통과 수와 생략
여부는 이 명령의 해당 실행 결과로 확인합니다. Vitest는 이미 설치된 로컬
경로를 `SOBAYA_TEST_VITEST_ROOT`로 지정할 수 있습니다. 검증 도중 패키지를
자동 다운로드하거나 실제 앱의 명세·테스트·구현을 변경하지 않습니다.

## 한계

가짜 워커 검사는 실제 Codex 인증·모델 접근이나 장시간 작업 품질·비용을
증명하지 않습니다. 외부 제공자는 공통 command 어댑터 계약을 구현해야 합니다.
세션 재사용과 통화 기준 예산 상한은 구현한 기능이 아닙니다. 테스트는 상태
전이와 오류 차단의 근거이며, 임의 앱 명세의 완전성을 보장하지 않습니다.

## 이번 전환에서 추가로 막은 우회

Git의 `skip-worktree`·`assume-unchanged` 플래그로 작업 파일 변경을 숨기면
작업 파일은 성공하지만 커밋에는 깨진 구현이 남을 수 있었습니다. 승인 전,
워커 실행 후, 커밋 전, 최종 게이트에서 이 플래그를 거부합니다. 회귀 검사는
거부 시 기존 HEAD·미완료 플랜·작업 파일·진단이 보존되는지도 확인합니다.

기존 계약 검사 36개의 동작은 [셸 검사 대응표](../tests/contract-coverage.md)에
매핑했습니다. 관련 단언을 묶은 케이스가 있어 이전 테스트 개수와 단순히
동일하다고 주장하지 않습니다. 실행 시나리오 25개는 그대로 유지하고 Git
플래그 우회 2개를 추가했습니다. 모델용 환경 변수는 하위 워커에만 전달하여
그 뒤 검증 스위트에 섞이지 않도록 했습니다.

## 최종 실행 결과

통합 저장소에서 `bash tests/run.sh`를 실행해 계약 **38개**, 실행 시나리오
**27개**, 도구 검사 **67개**가 모두 통과했습니다. 별도 next·probe·gate 셸
회귀 검사도 통과했으며, 인터프리터 차단용 실행 파일을 PATH 앞에 둔 상태에서
금지된 인터프리터 호출이 없음을 확인했습니다. 실제 Go·Node·Vitest를 사용했고,
실모델 API는 호출하지 않았습니다. ShellCheck 오류 수준 검사, Bash 구문 검사,
brain 인덱스·워크스페이스·실제 루트 훅 연결 검사도 통과했습니다.
