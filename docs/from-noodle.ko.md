# noodle에서 Sobaya로

Sobaya의 워크스페이스 방식은 [poteto/noodle](https://github.com/poteto/noodle)에서
빌려왔습니다. noodle은 파일 기반 작업 주문으로 모델 워커를 스케줄링하는
Go 런타임입니다. 이 문서는 출처 대응표이며 런타임 호환성을 뜻하지 않습니다.

| 원래 아이디어 | 현재 Sobaya의 적용 |
|---|---|
| 작업 주문과 단계별 실행 | 사람이 승인한 `failed-test.md`, 항목별 검증, 최종 게이트와 독립 리뷰 |
| 컨텍스트 브리프 | 관련 brain 노트·앱 상태·승인 상태·범위가 정해진 작업 지시 |
| 워커 프로세스 | 명시적 워커 정책; 기본 Codex/Astra와 범용 명령 어댑터 |
| 프로세스 종료와 산출물의 구분 | 워커 보고와 별도로 입력 무결성·테스트·진행 상황 검증 |
| 복구와 이어받기 | 승인과 진행 상태 기록; 보존된 상태를 확인한 뒤 명시적으로 재개 |
| 워크트리 격리 | 체크아웃당 작성자 한 명, 병렬 변경 격리, 순차 통합과 검증 |
| 재시도 전 진단 | 구조화된 진단 handoff; 설정 없는 모델 승급 금지 |
| brain·reflect·meditate | 영속 메모리, 선택적 읽기, 근거에 따른 유지보수 |
| 이벤트 기반 편의 기능 | 호스트 연결은 선택 사항; 명시적인 런타임·워크스페이스 검사 제공 |

Sobaya는 noodle의 데몬·스케줄러·웹 UI를 가져오지 않습니다. 독립적인 유용한
작업과 리뷰 위험도를 보고 위임하며, 파일이 바뀔 때마다 위임하지 않습니다.
과거 이전 노트와 보관한 플랜의 제공자 전용 훅은 역사 기록이며 현재 런타임의
사용 지침이 아닙니다.
